# 전체 페이지 와이어프레임

[설계 목차](README.md) · [상호작용 명세](interactions.md)

범례: `[버튼]`, `[입력 ______]`, `▾ 선택`, `○ 미선택 / ● 선택`, `⋯ 더보기`, `▸ 접힘 / ▾ 펼침`. 도식은 정보 우선순위를 표현하는 저해상도 와이어프레임이며 픽셀 크기는 설계 목차의 규격을 따른다. D는 데스크톱, M은 모바일이다. 태블릿은 각 화면의 별도 설명과 공통 반응형 규격을 따른다.

## P01 · 서비스 소개

```text
D ┌─────────────────────────────────────────────────────────────────┐
  │ ✈ Paperplane                                로그인  [시작하기] │
  │                                                                 │
  │ 새 이메일 주소로 받고,        ┌──────────────────────────────┐ │
  │ 원하는 메일함으로            │ shop@서비스도메인             │ │
  │ 전달하세요.                  │          ↓ 조건에 따라        │ │
  │                              │ me@example.com               │ │
  │ [내 이메일 만들기]           └──────────────────────────────┘ │
  │                                                                 │
  │ ① 주소 만들기          ② 메일함 인증          ③ 전달 설정       │
  │                                                                 │
  │ 필요한 메일만 전달하세요.                  [설정 예시 펼치기 ▾] │
  │ Paperplane                                                      │
  └─────────────────────────────────────────────────────────────────┘
M ┌────────────────────────────┐
  │ ✈ Paperplane       로그인 │
  │                            │
  │ 새 이메일 주소로 받고,    │
  │ 원하는 메일함으로         │
  │ 전달하세요.               │
  │ [내 이메일 만들기        ]│
  │ shop@서비스도메인         │
  │           ↓               │
  │ me@example.com            │
  │ ① 주소 만들기             │
  │ ② 메일함 인증             │
  │ ③ 전달 설정               │
  │ [설정 예시 펼치기 ▾      ]│
  └────────────────────────────┘
```

- ‘시작하기’는 P03, ‘로그인’은 P02. 이미 로그인했으면 주 버튼을 ‘내 이메일로 이동’으로 바꾼다.
- 설정 예시는 접이식 설명으로 ‘모든 메일’과 ‘제목에 영수증 포함’의 차이만 보여 준다. 실제 저장 버튼은 없다.
- 태블릿은 히어로를 한 열로 바꾸고 3단계 설명은 공간이 충분하면 가로 배치한다.
- 빈 운영 통계·가짜 고객 후기·‘전달 중’ 애니메이션을 넣지 않는다. 서비스 정책 문서는 실제 내용이 준비됐을 때 하단에 연결한다.

## P02 · 로그인

```text
D ┌──────────────────────────┬──────────────────────────────────────┐
  │ ✈ Paperplane             │ 로그인                               │
  │ 메일이 도착할 곳을       │ [Google로 계속하기                  ]│
  │ 간단하게 정하세요.       │ [Naver로 계속하기                   ]│
  │                          │ ───────── 또는 ─────────             │
  │ 주소 → 조건 → 메일함     │ 이메일 [                            ]│
  │                          │ 비밀번호 [                       ◉ ]│
  │                          │                         비밀번호 찾기│
  │                          │ [로그인                             ]│
  │                          │ 처음 오셨나요? 회원가입              │
  └──────────────────────────┴──────────────────────────────────────┘
M ┌────────────────────────────┐
  │ ✈ Paperplane              │
  │ 로그인                     │
  │ [Google로 계속하기        ]│
  │ [Naver로 계속하기         ]│
  │ ───────── 또는 ─────────  │
  │ 이메일 [                 ]│
  │ 비밀번호 [            ◉ ]│
  │             비밀번호 찾기 │
  │ [로그인                  ]│
  │ 처음 오셨나요? 회원가입   │
  └────────────────────────────┘
```

| 상태·행동 | 화면 변화 |
| --- | --- |
| 제출 | 버튼에 ‘로그인 중…’, 재제출 차단, 이메일·비밀번호 유지 |
| 자격 증명 오류 | 폼 상단 ‘이메일 또는 비밀번호를 확인해 주세요.’; 첫 오류 영역에 포커스 |
| 네트워크 실패 | 재시도 가능, 비밀번호는 메모리에만 유지 |
| 성공 | 돌아갈 내부 경로 또는 P10으로 이동 |
| 소셜 선택 | 버튼에 ‘로그인 페이지로 이동 중…’; 요청 성공 후 제공자 사이트로 이동 |
| 태블릿 | 설명 패널을 줄이고 중앙 최대 440px 폼 사용 |

비밀번호 표시 버튼은 누를 때마다 표시/숨김을 바꾸고 텍스트로 접근 가능한 이름을 제공한다. Caps Lock이 감지된 경우 보조 안내만 표시한다.

## P03 · 이메일 가입 시작

```text
D ┌──────────────────────────┬──────────────────────────────────────┐
  │ ✈ Paperplane             │ 이메일로 시작하기                    │
  │ 새 주소를 만들기 전에    │ ① 이메일  ─  ② 인증  ─  ③ 가입 정보 │
  │ 계정을 준비하세요.       │ 이메일 [                            ]│
  │                          │ 로그인에 사용할 이메일을 입력하세요.│
  │                          │ [인증번호 받기                      ]│
  │                          │ Google · Naver로 가입하기            │
  │                          │ 이미 계정이 있나요? 로그인           │
  └──────────────────────────┴──────────────────────────────────────┘
M ┌────────────────────────────┐
  │ ←  ✈ Paperplane           │
  │ 이메일로 시작하기         │
  │ 1 / 3 · 이메일            │
  │ 이메일 [                 ]│
  │ 로그인에 사용할 주소예요. │
  │ [인증번호 받기           ]│
  │ Google · Naver로 가입     │
  │ 로그인                    │
  └────────────────────────────┘
```

- 버튼 제출 전에 형식 검증, 서버 발송 성공 후 P04. 이메일을 잘못 입력했으면 P04에서 ‘주소 바꾸기’로 돌아온다.
- 발송 실패 시 현재 화면을 유지하고 ‘인증메일을 보내지 못했어요.’를 표시한다. 재시도는 사용자가 선택한다.
- 재발송 제한이면 서버 TTL에 맞춘 비활성 버튼과 ‘잠시 후 다시 요청할 수 있어요.’를 표시한다.
- 태블릿은 중앙 폼. 약관 동의 저장 API가 없으므로 동의를 수집·기록한 것처럼 구성하지 않는다.

## P04 · 가입 코드 확인

```text
D ┌──────────────────────────┬──────────────────────────────────────┐
  │ ✈ Paperplane             │ 이메일을 확인해 주세요               │
  │                          │ ① 이메일 ✓ ─ ② 인증 ─ ③ 가입 정보   │
  │                          │ me@example.com으로 보냈어요.         │
  │                          │ [주소 바꾸기]                        │
  │                          │ 인증번호 [ 0 0 0 0 0 0             ]│
  │                          │ [확인하고 계속하기                  ]│
  │                          │ [다시 보내기 · 00:24]                │
  └──────────────────────────┴──────────────────────────────────────┘
M ┌────────────────────────────┐
  │ ← 이메일 인증             │
  │ 2 / 3 · 인증              │
  │ me@example.com            │
  │ 으로 보냈어요. 주소 바꾸기│
  │ 인증번호                  │
  │ [ 0 0 0 0 0 0           ]│
  │ [확인하고 계속하기       ]│
  │ 다시 보내기 · 00:24       │
  └────────────────────────────┘
```

| 상태 | 변화 |
| --- | --- |
| 코드 입력 | 한 필드, 6자리 숫자만 허용, 붙여넣기·자동완성 지원 |
| 틀린 코드 | ‘인증번호를 확인해 주세요.’; 값을 선택해 바로 덮어쓸 수 있게 함 |
| 확인 제한 | 일반 요청 제한과 인증 시도 초과를 구분. 시도 초과이면 새 코드 요청 유도 |
| 만료·흐름 유실 | ‘인증을 다시 시작해 주세요.’ + P03 이동 |
| 재발송 성공 | 새 인증 상태로 교체, 코드 입력 비우기, 발송 알림 |
| 성공 | P05로 이동. 로그인 화면으로 보내지 않음 |

가입 인증은 최대 5회 확인 정책이다. 정확한 남은 횟수를 서버가 주지 않으므로 다른 탭의 시도까지 반영한 확정 수치처럼 표시하지 않는다. 태블릿은 중앙 단일 폼.

## P05 · 가입 정보 입력

```text
D ┌──────────────────────────┬──────────────────────────────────────┐
  │ ✈ Paperplane             │ 마지막으로 계정 정보를 입력하세요    │
  │                          │ ① 이메일 ✓ ─ ② 인증 ✓ ─ ③ 가입 정보 │
  │                          │ 인증한 주소 me@example.com           │
  │                          │ 이름 [                              ]│
  │                          │ 2~8자                                │
  │                          │ 비밀번호 [                       ◉ ]│
  │                          │ ○ 8자 이상  ○ 특수문자 포함          │
  │                          │ 비밀번호 확인 [                     ]│
  │                          │ [가입 완료                          ]│
  └──────────────────────────┴──────────────────────────────────────┘
M ┌────────────────────────────┐
  │ ← 가입 정보               │
  │ 3 / 3 · 계정 정보         │
  │ me@example.com · 인증 완료│
  │ 이름 [                   ]│
  │ 비밀번호 [            ◉ ]│
  │ ○ 8자 이상 ○ 특수문자    │
  │ 비밀번호 확인 [          ]│
  │ [가입 완료               ]│
  └────────────────────────────┘
```

- 조건 충족 표시는 입력 중 갱신하고, 빨간 오류는 첫 blur 또는 제출 이후에 보여 준다.
- 비밀번호 불일치는 확인 필드 아래에 표시한다. 이름·이메일의 최대 길이도 프런트에서 검증한다.
- 가입 요청은 인증 토큰을 소비할 수 있다. 실패 후 무조건 같은 토큰으로 재시도하지 않는다. 중복 계정이면 로그인 안내, 토큰 소진이면 이메일 재인증으로 복귀한다.
- 성공하면 P10 빈 상태로 이동. 새로고침으로 인증 컨텍스트가 사라지면 P03으로 복귀한다.
- 태블릿은 중앙 폼, 모바일 키보드가 열리면 버튼은 문서 아래에 배치한다.

## P06 · 소셜 콜백

```text
D ┌─────────────────────────────────────────────────────────────────┐
  │ ✈ Paperplane                                                    │
  │                    ⟳ 로그인 확인 중                             │
  │              잠시만 기다려 주세요.                              │
  │                  [로그인으로 돌아가기]                           │
  └─────────────────────────────────────────────────────────────────┘
M ┌────────────────────────────┐
  │ ✈ Paperplane              │
  │                            │
  │ ⟳ 로그인 확인 중          │
  │ 잠시만 기다려 주세요.     │
  │ [로그인으로 돌아가기     ]│
  └────────────────────────────┘
```

- 기존 회원이면 P10 또는 허용된 returnTo, 신규이면 P07. 가입 여부를 묻는 불필요한 선택 화면을 넣지 않는다.
- 제공자에서 취소한 경우 ‘로그인을 취소했어요.’, state 유실·재사용은 ‘로그인을 다시 시작해 주세요.’로 표시한다.
- 콜백 교환은 자동 반복하지 않는다. 요청 결과가 불명확하면 새 소셜 로그인부터 다시 시작한다.
- 리다이렉트 전의 세션 쿠키를 유지한다. 콜백에서 CSRF 세션을 먼저 재발급하여 OAuth state의 브라우저 연결을 깨뜨리지 않도록 한다. 검증에 필요한 기존 CSRF 값이 유실되면 로그인부터 재시작한다.
- 모든 화면 폭에서 중앙 상태 패널. 접근성 알림은 최초 처리 시작과 성공·실패 때만 읽는다.

## P07 · 소셜 신규 가입

```text
D ┌──────────────────────────┬──────────────────────────────────────┐
  │ ✈ Paperplane             │ 사용할 이름을 알려 주세요            │
  │                          │ Google 로그인 확인 완료              │
  │                          │ 이름 [                              ]│
  │                          │ 2~8자로 입력해 주세요.               │
  │                          │ [가입 완료                          ]│
  └──────────────────────────┴──────────────────────────────────────┘
M ┌────────────────────────────┐
  │ ✈ Paperplane              │
  │ 사용할 이름을 알려 주세요│
  │ Google 로그인 확인 완료   │
  │ 이름 [                   ]│
  │ 2~8자                     │
  │ [가입 완료               ]│
  └────────────────────────────┘
```

Google/Naver 이름은 실제 제공자에 따라 표시한다. API가 주지 않는 프로필 사진·이메일·이름을 추측해서 채우지 않는다. 내부 providerId는 화면에 노출하지 않는다. 실패·만료 시 P02에서 소셜 로그인을 다시 시작한다. 태블릿은 중앙 폼.

## P08 · 비밀번호 복구와 코드 확인

```text
D ┌──────────────────────────┬──────────────────────────────────────┐
  │ ✈ Paperplane             │ 비밀번호를 재설정할까요?             │
  │                          │ 이메일 [                            ]│
  │                          │ [인증번호 받기                      ]│
  │                          │ 소셜 가입은 Google/Naver로 로그인해요.│
  │                          │ 로그인으로 돌아가기                  │
  └──────────────────────────┴──────────────────────────────────────┘
M ┌────────────────────────────┐
  │ ← 비밀번호 재설정         │
  │ 이메일 [                 ]│
  │ [인증번호 받기           ]│
  │ 소셜 가입은 해당 서비스로│
  │ 로그인해 주세요.          │
  └────────────────────────────┘

발송 후 같은 패널 교체:
  이메일 입력 → 수신 주소 요약 + 코드 입력 + [확인] + [다시 보내기]
```

코드 확인 배치는 P04를 재사용하되 단계 제목을 ‘비밀번호 재설정’으로 유지한다. 성공 시 P09. 서버가 검증 요청을 거절하면 ‘입력한 이메일과 가입 방식을 확인해 주세요.’를 표시하고 가입 여부를 임의로 확정하지 않는다. 태블릿은 중앙 폼.

## P09 · 새 비밀번호와 완료

```text
D ┌──────────────────────────┬──────────────────────────────────────┐
  │ ✈ Paperplane             │ 새 비밀번호                          │
  │                          │ 새 비밀번호 [                    ◉ ]│
  │                          │ ○ 8자 이상 ○ 특수문자 포함           │
  │                          │ 비밀번호 확인 [                     ]│
  │                          │ [비밀번호 변경                      ]│
  └──────────────────────────┴──────────────────────────────────────┘
M ┌────────────────────────────┐
  │ 새 비밀번호               │
  │ 비밀번호 [            ◉ ]│
  │ ○ 8자 이상 ○ 특수문자    │
  │ 확인 [                   ]│
  │ [비밀번호 변경           ]│
  └────────────────────────────┘

완료 패널:
  ✓ 비밀번호를 변경했어요.
  다시 로그인해 주세요.
  [로그인으로 이동]
```

성공 시 앱의 기존 인증 상태와 보호된 데이터를 지운다. 자동 로그인하거나 이전 화면에 인증된 상태로 복귀하지 않는다. 변경 요청 실패 후 인증 상태가 소비됐으면 P08부터 다시 진행한다. 태블릿은 중앙 폼.

## P10 · 내 이메일

```text
D ┌───────────────┬─────────────────────────────────────────────────┐
  │ ✈ Paperplane  │ 내 이메일  12개                    [주소 만들기]│
  │ ● 내 이메일  │ 원하는 메일함으로 받을 주소를 관리하세요.       │
  │ 받는 메일함   │                                                 │
  │ 전달 기록     │ shop@서비스도메인 [복사]                    ⋯  │
  │               │ 모든 메일 → me@example.com   설정 완료 [설정]  │
  │               │ ────────────────────────────────────────────── │
  │               │ work@서비스도메인 [복사]                    ⋯  │
  │               │ 전달 규칙이 없어요.          설정 필요 [설정]  │
  │               │                                                 │
  │ 계정 설정     │                          [이전] 1 / 2 [다음]   │
  └───────────────┴─────────────────────────────────────────────────┘
M ┌────────────────────────────┐
  │ ✈ Paperplane         계정 │
  │ 내 이메일 12개            │
  │ [주소 만들기             ]│
  │ ┌────────────────────────┐│
  │ │ shop@서비스도메인  ⋯  ││
  │ │ [복사]                ││
  │ │ 모든 메일 → me@…      ││
  │ │ 설정 완료 [전달 설정] ││
  │ └────────────────────────┘│
  │ [이전]    1 / 2    [다음]│
  │ 내 이메일 | 메일함 | 기록│
  └────────────────────────────┘
```

| 상태 | 화면 변화 |
| --- | --- |
| 첫 로딩 | 제목 아래 3개 행 스켈레톤, 페이지 번호 미표시 |
| 주소 없음 | 비행기 아이콘 + ‘첫 이메일 주소를 만들어 보세요.’ + 만들기 버튼 하나 |
| 규칙 없음 | 해당 행에 ‘설정 필요’, ‘설정하기’ 강조 |
| 미인증 목적지 포함 | ‘메일함 인증 필요’와 설정 진입. 모든 규칙이 동작하는 것처럼 완료 표시하지 않음 |
| 추가 페이지 로드 | 현재 행 유지, 목록에 갱신 중 표시, 페이지 버튼만 잠금 |
| 조회 실패 | 목록 영역에 오류와 재시도. 기존 데이터가 있으면 ‘최신 상태를 불러오지 못했어요.’ |
| 복사 | 해당 버튼에 짧게 ‘복사됨’, 실패하면 수동 복사 안내 |
| 더보기 | 주소 삭제 메뉴. 바깥 클릭·Escape 닫기, 키보드 접근 가능 |

태블릿은 상단 탐색과 2줄 목록 행. ‘12개’는 서버 total이며 현재 페이지 길이로 대신하지 않는다. 페이지에 항목이 없고 전체는 존재하면 마지막 유효 페이지로 이동한다. 데이터 로딩 전 빈 화면을 깜박이지 않는다.

## P11 · 주소 만들기

```text
D ┌───────────────┬─────────────────────────────────────────────────┐
  │ ✈ Paperplane  │ ← 내 이메일                                    │
  │ 내 이메일     │ 주소 만들기                                    │
  │ 받는 메일함   │ ① 주소 만들기 → ② 받는 메일함 → ③ 전달 설정    │
  │ 전달 기록     │                                                 │
  │               │ [shop             ] @ [서비스도메인        ▾] │
  │               │ 새 주소: shop@서비스도메인                     │
  │               │ 생성한 주소는 나중에 수정할 수 없어요.         │
  │               │ [취소]                    [주소 만들고 계속]  │
  └───────────────┴─────────────────────────────────────────────────┘
M ┌────────────────────────────┐
  │ ← 주소 만들기             │
  │ 1 / 3 · 주소              │
  │ 주소 앞부분 [            ]│
  │ 도메인 [서비스도메인   ▾ ]│
  │ shop@서비스도메인         │
  │ 나중에 수정할 수 없어요.  │
  │                            │
  │ [취소] [주소 만들고 계속] │
  └────────────────────────────┘
```

- 도메인 하나면 읽기 전용으로 표시하고 여러 개면 선택한다. 도메인 로딩 중 제출을 잠근다.
- 전체 주소를 조합해 형식·길이를 검증한다. 서버에 없는 사전 중복 조회를 흉내 내지 않는다.
- 중복 오류는 앞부분 필드 아래에 표시하고 입력을 유지한다. 서버가 정규화한 주소를 성공 후 표시한다.
- 성공하면 생성된 주소 ID와 함께 P12에서 첫 전달 추가를 시작한다. 기존 목록의 페이지를 무조건 1로 간주하지 말고 목록 재조회 결과를 사용한다.
- 취소는 P10. 요청 중에는 취소·뒤로를 눌러도 서버 생성이 취소되지 않을 수 있으므로 목록 복귀 후 재조회한다.
- 태블릿은 폼 최대 720px, 주소와 도메인이 좁으면 두 줄로 배치.

- 규칙 없는 상태는 ‘아직 받는 메일함을 연결하지 않았어요.’와 ‘전달 설정하기’. 전체 전달이 암묵적으로 작동한다고 표현하지 않는다.
- 하나의 규칙에 복수 조건 그룹이 있으면 자연어 요약 2줄과 ‘조건 자세히’ 접기를 제공한다. 전체 요약에서 목적지를 중복으로 숨기지 않는다.
- 삭제는 각 규칙의 더보기. 마지막 규칙 삭제 후 ‘설정 필요’로 전환한다.
- 기존 규칙의 목적지가 미인증이면 해당 카드에 ‘메일함 인증 필요’와 인증하기 버튼. 성공 후 재조회하고 원래 설정으로 돌아온다.
- 모바일은 뒤로 버튼 중심의 상세 페이지, 하단 탐색 없음. 태블릿은 카드 폭만 확장한다.
- 직접 진입 시 목록 페이지에서 주소를 찾지 못하면 P18 일반 404 대신 ‘주소를 찾을 수 없어요.’와 목록 복귀를 이 영역에 표시한다.

1440px 미만에서는 우측 요약을 폼 아래로 이동한다. 태블릿도 한 열 폼. API상 전달 대상은 레코드당 한 개이므로 다중 선택 체크박스를 쓰지 않는다.

**기본 상태**: 받는 메일함 미선택, ‘모든 메일’ 선택. 인증된 메일함이 하나여도 자동 선택했다면 명확히 표시한다. 기존 규칙 수정은 저장된 값을 그대로 복구한다.

**메일함 선택 상태**: 검색 가능한 목록이 필요하면 로드된 전체 destinations 안에서만 검색하며 검색 범위를 설명할 필요 없이 전체 목록을 대상으로 동작한다. 목록에는 인증된 주소만 표시한다. 빈 목록이면 ‘메일함 인증하기’ 버튼으로 P15를 연다. 모바일은 네이티브 선택 또는 전체 너비 선택 패널을 사용한다.

**조건 추가 상태**: 필드 선택 → 비교 방식 → 값 입력. 추가 후 새 필드로 포커스 이동. 뉴스레터·날짜·첨부파일은 전용 입력으로 바뀐다. 자세한 구조·변환은 상호작용 문서의 조건 편집기를 따른다.

**편집 이탈**: 바뀐 값이 있을 때만 취소 확인. P15로 이동할 때는 허용된 하위 흐름이므로 초안을 메모리에 보존하며 이탈 경고를 띄우지 않는다. 뒤로 돌아오면 복구한다. 브라우저 리로드는 복구를 보장하지 않는다.

**저장 중**: 저장 버튼 ‘저장 중…’, 해당 폼의 변경·중복 제출 차단. 성공하면 P12, 첫 규칙이면 P20. 저장 실패는 값 유지. 404이면 편집 대상이 사라졌음을 알리고 목록으로 복귀한다.

## P15 · 받는 메일함 추가·인증

```text
D ┌───────────────┬─────────────────────────────────────────────────┐
  │ ✈ Paperplane  │ ← 받는 메일함                                  │
  │ 내 이메일     │ 받을 메일함을 연결하세요                        │
  │ 받는 메일함   │ 이메일 [me@example.com                       ] │
  │ 전달 기록     │ 기존에 사용하는 외부 이메일을 입력하세요.      │
  │               │ [인증번호 받기]                                 │
  └───────────────┴─────────────────────────────────────────────────┘
M ┌────────────────────────────┐
  │ ← 메일함 추가             │
  │ 이메일 [                 ]│
  │ 기존에 사용하는 주소예요. │
  │ [인증번호 받기           ]│
  └────────────────────────────┘

코드 발송 후 D/M 공통 구성:
  me@example.com으로 보냈어요. [주소 바꾸기]
  인증번호 [ 0 0 0 0 0 0 ]

  유효시간 09:58
  [메일함 연결]
  [다시 보내기 · 00:58]
```

- 도메인이 서비스 도메인이면 필드 아래에 ‘기존에 사용 중인 외부 이메일을 입력해 주세요.’.
- 6자리 완성 후 자동 제출하지 않는다. 실패하면 입력을 재활성화하지 않고 ‘인증번호를 다시 받아 주세요.’와 새 요청 버튼으로 교체한다.
- 만료 타이머는 응답의 expiresIn 기준이며 클라이언트 안내다. 서버가 최종 판단한다.
- 성공하면 ‘메일함을 연결했어요.’ 알림 후, 목록에서 왔으면 P14, 편집에서 왔으면 P13으로 돌아가 새 목적지를 선택한다.
- 태블릿은 중앙 640px 폼. 서버 상태 유실·새로고침 시 첫 입력 단계부터 시작한다.

## P16 · 전달 기록과 상세

```text
D ┌───────────────┬─────────────────────────────────────────────────┐
  │ ✈ Paperplane  │ 전달 기록                         [새로고침]   │
  │ 내 이메일     │ 메일의 전달 처리 결과를 확인하세요.             │
  │ 받는 메일함   │                                                 │
  │ ● 전달 기록  │ 기록 시각     내 이메일 → 받는 메일함    결과   │
  │               │ 10/17 12:30  shop@… → me@…             성공 ▸  │
  │               │ 10/17 12:28  work@… → work@…           실패 ▾  │
  │               │ ┌ 상세 ──────────────────────────────────────┐│
  │               │ │ 기록: 2026-10-17 12:28 (로컬 시간)         ││
  │               │ │ 응답: 목적지 서버가 요청을 거절했습니다.   ││
  │               │ │ 메시지 ID: … [복사]                       ││
  │               │ └───────────────────────────────────────────┘│
  │               │                            [이전] 1 / 4 [다음]│
  └───────────────┴─────────────────────────────────────────────────┘
M ┌────────────────────────────┐
  │ ✈ Paperplane         계정 │
  │ 전달 기록      [새로고침] │
  │ ┌────────────────────────┐│
  │ │ 전달 실패 · 12:28     ││
  │ │ work@서비스도메인    ││
  │ │ → work@example.com   ││
  │ │ [상세 보기 ▾]        ││
  │ │ 응답: …              ││
  │ │ 메시지 ID: … [복사] ││
  │ └────────────────────────┘│
  │ [이전]  1 / 4  [다음]    │
  │ 내 이메일 | 메일함 | 기록│
  └────────────────────────────┘
```

- 상세는 행 바로 아래 펼친다. 페이지 전환 시 펼침 상태를 초기화한다. 데스크톱·모바일 모두 새 모달을 열지 않는다.
- detail은 원문을 일반 텍스트로 렌더링한다. 위 도식의 문구는 예시이며 실제 오류를 임의로 번역·추론하지 않는다. 값이 없으면 ‘추가 설명이 없어요.’.
- 각 행의 시각은 기록 시각이다. ‘방금’ 등 상대 표시는 전체 날짜·시간에 접근할 수 있게 보조 표시한다.
- 같은 messageId라도 중간 이벤트를 최종 실패로 단정하지 않는다. 재시도 이벤트는 ‘재시도 기록’으로 표시한다.
- 빈 목록, 로딩, 재조회 실패는 P10의 패턴을 따른다. 빈 목록만으로 서버 장애를 표시하지 않는다.
- 태블릿은 시각+결과, 경로를 두 줄 행으로 배치한다. 제목·본문·전체 검색·필터·재전송 버튼은 없다.

## P17 · 계정 설정

```text
D ┌───────────────┬─────────────────────────────────────────────────┐
  │ ✈ Paperplane  │ 계정 설정                                      │
  │ 내 이메일     │ 프로필                                         │
  │ 받는 메일함   │ 이름 [테스터                    ] [변경 저장]  │
  │ 전달 기록     │                                                 │
  │               │ 로그인 정보                                    │
  │               │ 로그인 방식  이메일                            │
  │               │ 이메일       me@example.com                    │
  │               │ [비밀번호 재설정]                              │
  │               │ ────────────────────────────────────────────── │
  │ ● 계정 설정  │ [로그아웃]                                     │
  │               │ 계정 삭제                                      │
  │               │ 주소와 전달 설정, 기록이 함께 삭제됩니다.      │
  │               │ [계정 삭제]                                    │
  └───────────────┴─────────────────────────────────────────────────┘
M ┌────────────────────────────┐
  │ ← 계정 설정               │
  │ 프로필                    │
  │ 이름 [테스터             ]│
  │ [변경 저장               ]│
  │ 로그인 방식 · 이메일      │
  │ me@example.com            │
  │ [비밀번호 재설정         ]│
  │ [로그아웃                ]│
  │ ───────────────────────── │
  │ 계정 삭제                 │
  │ 주소·설정·기록이 삭제돼요.│
  │ [계정 삭제               ]│
  └────────────────────────────┘
```

- 이름이 바뀌었고 유효할 때 저장 가능. 저장 성공 후 화면의 사용자 표시를 함께 갱신한다.
- 소셜 계정은 ‘Google’ 또는 ‘Naver’만 표시하고 제공되지 않은 이메일 행·비밀번호 재설정 버튼은 숨긴다.
- 로그아웃은 클릭하면 서버 세션 폐기를 진행한다. 실패했는데 ‘로그아웃 완료’라고 알리지 않는다. 로컬 인증 정보를 정리했더라도 서버 폐기 미확인은 별도 안내한다.
- 탈퇴는 별도 확인 대화상자, 확인 체크 후 제출. 성공 후 사용자 데이터 캐시를 지우고 P01에 완료 알림을 표시한다.
- 태블릿은 섹션을 한 열로 유지하며, 계정 삭제 영역은 충분히 분리한다.

## P18 · 찾을 수 없는 페이지

```text
D ┌─────────────────────────────────────────────────────────────────┐
  │ ✈ Paperplane                                                    │
  │                    페이지를 찾을 수 없어요.                     │
  │             주소가 바뀌었거나 없는 페이지일 수 있어요.          │
  │               [이전 화면]  [내 이메일 / 처음으로]                │
  └─────────────────────────────────────────────────────────────────┘
M ┌────────────────────────────┐
  │ ✈ Paperplane              │
  │ 페이지를 찾을 수 없어요. │
  │ 주소를 확인해 주세요.     │
  │ [이전 화면               ]│
  │ [처음으로                ]│
  └────────────────────────────┘
```

로그인이 확인됐으면 ‘내 이메일’, 아니면 ‘처음으로’. 유효한 앱 내부 이전 경로가 없으면 이전 화면 버튼은 생략한다. 자동 리다이렉트로 메시지를 읽을 시간을 빼앗지 않는다. 태블릿도 중앙 패널.

## P19 · 세션 복구·서비스 오류

```text
D ┌───────────────┬─────────────────────────────────────────────────┐
  │ ✈ Paperplane  │ ⟳ 로그인 상태를 확인하고 있어요.               │
  │ 비활성 탐색   │                                                 │
  │               │ [사용자 데이터는 확인 전 표시하지 않음]        │
  └───────────────┴─────────────────────────────────────────────────┘
M ┌────────────────────────────┐
  │ ✈ Paperplane              │
  │ ⟳ 로그인 확인 중          │
  │ 잠시만 기다려 주세요.     │
  └────────────────────────────┘

로그인 만료:
  로그인이 만료됐어요.
  다시 로그인한 뒤 계속해 주세요.
  [로그인]

필수 데이터 조회 실패:
  정보를 불러오지 못했어요.
  연결을 확인한 뒤 다시 시도해 주세요.
  [다시 시도] [이전 화면]
```

재로그인과 네트워크 재시도를 섞지 않는다. 단순 네트워크 오류를 로그인 만료로 처리하면 정상 세션을 잃게 된다. 기존 데이터가 있으면 전체 오류 페이지 대신 해당 영역 배너를 사용한다. 로그인 상태를 확정하기 전 이전 사용자 정보를 보여 주지 않는다. 태블릿은 중앙 메시지 또는 기존 본문 내 오류 패널.

## P20 · 첫 설정 완료

```text
D ┌───────────────┬─────────────────────────────────────────────────┐
  │ ✈ Paperplane  │ ✓ 전달 설정을 저장했어요.                       │
  │ 내 이메일     │                                                 │
  │ 받는 메일함   │ shop@서비스도메인                               │
  │ 전달 기록     │              ↓ 모든 메일                        │
  │               │ me@example.com                                  │
  │               │                                                 │
  │               │ 새 주소를 필요한 곳에 사용해 보세요.            │
  │               │ [주소 복사]                [설정 확인]          │
  └───────────────┴─────────────────────────────────────────────────┘
M ┌────────────────────────────┐
  │ ✓ 설정을 저장했어요.     │
  │                            │
  │ shop@서비스도메인         │
  │           ↓ 모든 메일     │
  │ me@example.com            │
  │                            │
  │ [주소 복사               ]│
  │ [설정 확인               ]│
  └────────────────────────────┘
```

실제 API 저장 성공 후에만 표시한다. ‘메일 전달 성공’ 문구·가짜 성공 기록을 넣지 않는다. SMTP 운영 연결이 검증되지 않은 개발·미리보기 환경에서는 이 화면에도 ‘설정 미리보기이며 실제 전달은 아직 확인되지 않았습니다.’라는 환경 안내를 별도로 붙인다. 이 안내를 빈 전달 기록으로 추론하지 않는다. 태블릿은 중앙 패널. 이후 같은 주소 편집 저장은 짧은 성공 알림과 P12 복귀로 충분하다.

## 화면 공통 오버레이 도면

삭제 확인 — 데스크톱은 중앙 최대 440px, 모바일은 좌우 16px 여백의 중앙 대화상자. 길면 내부 콘텐츠만 스크롤한다.

```text
┌──────────────────────────────────┐
│ 이 메일함을 삭제할까요?       [×]│
│ me@example.com                   │
│ 이 메일함으로 연결된 전달 규칙도 │
│ 함께 삭제됩니다.                 │
│                                  │
│ [취소]             [메일함 삭제]│
└──────────────────────────────────┘
```

미저장 확인:

```text
┌──────────────────────────────────┐
│ 작성 중인 내용을 나갈까요?      │
│ 저장하지 않은 변경 내용은       │
│ 사라집니다.                      │
│ [계속 작성]       [나가기]       │
└──────────────────────────────────┘
```

토스트 — 데스크톱 우하단, 모바일은 하단 탐색·저장 영역 위. 성공 확인만 토스트에 의존하지 않고 변경된 화면에도 결과를 반영한다. 중요한 오류·삭제 영향은 토스트에만 넣지 않는다.

```text
✓ 주소를 복사했어요.          [닫기]
```
